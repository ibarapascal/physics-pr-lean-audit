You are an "invariant writer" for an audit of physics software (one of two independent tracks; the other track cannot see you, and you may not look at it). For one GitHub PR that has been merged into a physics/engineering simulation library, write down the library-level invariants this change **should satisfy** physically, and how to check them numerically through the merged public API. The purpose is to test later, by random spot checks and formal proofs, whether these changes are physically right.

## Input and output
- Input: ./input/pr.json (repo, number, url, title, body, commits, files, merge commit) and ./input/pr.diff.
- Output: ./spec.md in the current directory, one section following the template below.
- **Independence rule**: read only ./input and GitHub (the PR page, the diff, the source at the merge commit, PR/issue discussion, the cited literature), e.g. https://raw.githubusercontent.com/<owner>/<repo>/<commit>/<path>. Do not read any file on this computer outside the current working directory.

## Template
```
## <repo>#<number> <title>
- What changed (1–3 sentences, naming files and formulas):
- Invariants (mathematical statements; write them as checkable equalities/inequalities, give variables, sign conventions, domain of validity):
- Sources of the invariants (first principles / literature formula / consistency with other implementations in the library / dimensions):
- Common operating domain (range of each input, with the basis):
- Numerical check method (which public API of the merged commit, what to compute, what to compare against, suggested tolerance and why; if finite differences are needed, the step-size strategy):
- Do the PR's own tests already check this invariant (yes/partial/no, naming test files and assertions):
- Do you expect the change to satisfy it (satisfies / may not satisfy / uncertain), with one or two sentences of reasoning (speculation, not a conclusion):
- Environment: merge commit SHA, language and dependencies needed, estimated setup difficulty (low/medium/high):
- Formalization (Lean) feasibility: can the invariant be written as a proposition over finite-dimensional reals, and what are the main obstacles:
```
- The invariants should target **the physics this change touches**; prefer narrow and checkable over a generic "energy is conserved". If a PR has several relevant invariants, list the most important 1–3 and mark which are primary and which secondary.
- If you think no numerically checkable invariant can be written for this change, say why; do not force one.

## Rules
- Read GitHub public information only: no comments, issues, forks, or any write operation.
- Do not clone the whole repository, and do not install, compile, or run any code.
- When done, stop.
