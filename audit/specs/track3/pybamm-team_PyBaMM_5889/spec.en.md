## pybamm-team/PyBaMM#5889 fix: look up Chayambuka2022 NVPF diffusivity at the solid concentration

- What changed (1–3 sentences, naming files and formulas):
  `NVPF_diffusivity_Chayambuka2022(sto, T)` in `packages/pybamm/src/pybamm/input/parameters/sodium_ion/Chayambuka2022.py` changes the lookup coordinate from `sto * Initial concentration in electrolyte` to `sto * Maximum concentration in positive electrode`, i.e. from θ cₑ,₀ to the solid concentration cₛ = θ C. The default C = 15320 mol m⁻³, whereas cₑ,₀ = 1000 mol m⁻³; `test_Chayambuka2022.py` at the same time adds a regression point for the positive-electrode diffusion coefficient, switches to relative tolerances and corrects other expected values, and the CHANGELOG and the output of the sodium-ion example notebook are also updated. The correction of the expected value of the electrolyte diffusion coefficient does not correspond to a new electrolyte physics implementation.

- Invariants (mathematical statements; write them as checkable equalities/inequalities, give variables, sign conventions, domain of validity):
  Let θ be the dimensionless sodium site fraction of the positive-electrode particle, C > 0 the maximum solid concentration of the positive electrode, cₛ = θ C, e = cₑ,₀ the initial electrolyte concentration, and T₀ = 298.15 K. Let the ordered data of `data/D_p.csv` at the merge commit be (xᵢ, dᵢ), with x in mol m⁻³ and d in m² s⁻¹; define L(c) as the piecewise linear interpolation of this table. Let D(θ,T;C,e) denote the output of the public positive-electrode diffusion coefficient function after parameter processing.

  1. **Primary — the solid-concentration coordinate is consistent with the table.** For xᵢ ≤ θ C ≤ xᵢ₊₁, let λ = (θ C − xᵢ)/(xᵢ₊₁ − xᵢ); we should have
     D(θ,T₀;C,e) = L(θ C) = (1−λ)dᵢ + λdᵢ₊₁.
     In particular D(xᵢ/C,T₀;C,e) = dᵢ. The normalizing transformation should also satisfy D(c/C₁,T₀;C₁,e) = D(c/C₂,T₀;C₂,e), provided the same concentration table is kept and both site fractions lie in [0,1]. This is a check of the semantics of the parameter coordinate, and does not claim that different materials share the same diffusion curve.
  2. **Secondary — the solid-material diffusion coefficient does not depend on an unrelated electrolyte initial condition.** Fixing θ, C, T₀ and the data table, for any e₁,e₂ in the test domain we should have D(θ,T₀;C,e₁) = D(θ,T₀;C,e₂). This condition concerns only this local constitutive function; changing e can change the trajectory of the whole cell through electrolyte transport and reaction kinetics, so voltage or capacity is not required to remain unchanged.
  3. **Secondary — positive diffusion within the table and the local envelope.** For each interval above, 0 < min(dᵢ,dᵢ₊₁) ≤ D ≤ max(dᵢ,dᵢ₊₁). Over the whole table further 1.95×10⁻¹⁷ ≤ D ≤ 2.51×10⁻¹⁵ m² s⁻¹. With the concentration gradient g = ∇cₛ positive in the direction of increasing concentration, and the Fick flux J = −Dg, we have J·g = −D‖g‖² ≤ 0, strictly less than zero for g ≠ 0. This local dissipation sign inequality is not equivalent to a proof of stability or energy conservation of the whole DFN discretized system. The data are themselves non-monotonic, and D should not be required to be globally monotonic in θ.

- Sources of the invariants (first principles / literature formula / consistency with other implementations in the library / dimensions):
  The main evidence is the merged commit's [Chayambuka2022 parameter source](https://github.com/pybamm-team/PyBaMM/blob/eda03ed6d1003b186cc2d70ad8b3240a7b6350f1/packages/pybamm/src/pybamm/input/parameters/sodium_ion/Chayambuka2022.py) and the [D_p.csv raw table and unit header](https://github.com/pybamm-team/PyBaMM/blob/eda03ed6d1003b186cc2d70ad8b3240a7b6350f1/packages/pybamm/src/pybamm/input/parameters/sodium_ion/data/D_p.csv). The definition of the site fraction θ = cₛ/C gives the first item; the negative-electrode `HC_diffusivity_Chayambuka2022` in the same file also multiplies θ by the maximum concentration of that electrode. Dimensions alone cannot identify the original error, because e and C have the same dimension, and the physical identities of the solid phase and the electrolyte must be distinguished.
  The [Interpolant source](https://github.com/pybamm-team/PyBaMM/blob/eda03ed6d1003b186cc2d70ad8b3240a7b6350f1/packages/pybamm/src/pybamm/expression_tree/interpolant.py) confirms that the default one-dimensional interpolation is linear; hence the convex-combination formula and the envelope belong to the constitutive-representation convention of this library. The second item comes from the assumption of this parameter model that the solid diffusion is a function of the solid concentration; the flux sign of the third item comes from Fick's law and the positive-diffusion requirement. The source cites K. Chayambuka et al., "Physics-based modeling of sodium-ion batteries part II. Model and validation", Electrochimica Acta 404 (2022), 139764, DOI 10.1016/j.electacta.2021.139764, and notes that the parameters come from a COMSOL example; this audit did not independently read the paper or COMSOL, so the accuracy of the table against the original experiments is not regarded as verified, and no additional temperature dependence is inferred.

- Common operating domain (range of each input, with the basis):
  The core physical domain fixes C = 15320 mol m⁻³, T = 298.15 K, e = 1000 mol m⁻³, based on the defaults of this parameter set. Table accuracy is claimed only on cₛ ∈ [131.578947, 15197.36842] mol m⁻³ where data are provided, i.e. θ ∈ [131.578947/15320, 15197.36842/15320], about [0.0085887, 0.991995]. The end extrapolation over the whole [0,1] is not regarded as a verified physical domain: this Interpolant allows extrapolation by default, but there are no data outside the table to support it.
  For the second item, e ∈ [500,1500] mol m⁻³ is used as a finite perturbation domain around the default; this is a test choice for identifying erroneous coupling, not a literature-verified cell operating concentration range. For the coordinate transformation of the first item, use C₁,C₂ ∈ [15320,18384] mol m⁻³ (1–1.2 times the default), keeping cₛ inside the original table, then take θⱼ = cₛ/Cⱼ; this domain guarantees θⱼ ∈ (0,1) and is used only for algebraic consistency tests. For the flux sign check, one can choose g = (10⁶ mol m⁻⁴)u, u ∈ [−1,1]³, including zero and mixed-sign directions; the magnitude is only a test scale to avoid floating-point extremes, not an additional material applicability range. The parameter T is accepted by the function but not used by the current function; the temperature invariance of the real material is not listed as a physical invariant.

- Numerical check method (which public API of the merged commit, what to compute, what to compare against, suggested tolerance and why; if finite differences are needed, the step-size strategy):
  The following is a scheme for later execution; this time PyBaMM was not installed, imported or run, and there are no numerical verification results.
  Use `p = pybamm.ParameterValues("Chayambuka2022")`, and as needed set the full names `"Maximum concentration in positive electrode [mol.m-3]"` and `"Initial concentration in electrolyte [mol.m-3]"` with `p.update({...})`. Construct `expr = p["Positive particle diffusivity [m2.s-1]"](pybamm.Scalar(theta), pybamm.Scalar(298.15))`, and obtain the value with `p.evaluate(expr)` (if a single-element array is returned, extract that element). For each group of C, e use a new ParameterValues and expression, so that caching or earlier processing does not contaminate the check.
  Read the two columns of the CSV at the pinned merge commit independently, without recovering expected values from the children or internal x/y of the expression under test, and without calling `pybamm.Interpolant` again as the oracle. First confirm that x is strictly increasing and d > 0, then compute L directly with the two-point convex combination above.
  The first item checks all 34 nodes and the 33 interval midpoints, and samples several λ ∈ (0,1) in each interval, with θ = ((1−λ)xᵢ+λxᵢ₊₁)/C. Cover the end points and the neighborhoods of local extrema, and carry out the paired comparison with different C and the same cₛ described above. For the unrounded CSV oracle a tolerance of `abs(D−L)/abs(L) ≤ 1e−10` with zero absolute tolerance is suggested; this is a double-precision arithmetic consistency check on the same decimal table, the tolerance leaves margin for floating-point coordinate conversion and interval location, and does not represent experimental accuracy.
  The second item compares, for the same θ, C, with e = 500, 1000, 1500 and random values in the interval, the relative error pairwise ≤ 1e−12, with zero absolute tolerance. The original implementation would depend on e, so this check can distinguish a concentration-identity error; the correct expression does not reference e, and the expected difference is zero.
  The third item reuses all samples, first requiring finite and D > 0, then checking the local lower and upper bounds, allowing a floating-point margin of `1e−10 * max(dᵢ,dᵢ₊₁)` at the boundaries. Construct J from the D returned by the API and the chosen g, and check J·g ≤ 0; this step only checks the constitutive consequence, and does not claim to execute the library's full flux discretization. The strict positivity check of D cannot be replaced by a large absolute tolerance.
  Additional published regression points can be taken as θ = 0.3, 0.5, 0.9, corresponding to about 5.6673e−17, 8.3317e−17, 3.5627e−17 m² s⁻¹; a relative tolerance of 1e−4 suffices for these rounded values. No finite differences are needed: direct substitution into the table lookup formula and the paired parameter tests suffice, and the piecewise linear interpolation is generally not differentiable at the nodes. The 1C/2C cutoff capacities in the PR description are only multi-factor simulation results, and are not used as hard oracles here.

- Formalization (Lean) feasibility: can the invariant be written as a proposition over finite-dimensional reals, and what are the main obstacles:
  Yes. Embed the 34 rational nodes and positive coefficients in ℝ and define the piecewise affine L; assuming xᵢ < xᵢ₊₁, C > 0, λ ∈ [0,1], the first item and the concentration reparameterization reduce to multiplicative and divisive algebraic identities, the second reduces to e not appearing in the definition, and the third reduces to bounds of a convex combination of positive numbers and the nonnegativity of the squared norm in a finite-dimensional inner-product space. These three propositions can be expressed without formalizing PDEs or time integration.
  The main obstacle is proving that the actual Python parameter substitution and SciPy interpolation execution refine this real-number definition, and handling IEEE-754 rounding and node branches; a proof at the real-number level does not automatically prove machine-precision error bounds. The experimental source of the data table and the material-physics interpretation of θ remain external modeling premises, and cannot be derived from these algebraic proofs.
